SLIDE 2 — PROBLEM STATEMENT
================================================================================

• Brain tumors are among the most lethal neurological disorders.
• Manual MRI analysis is time-consuming and prone to fatigue-related error.
• Existing systems lack:
    - Encrypted transmission/storage of sensitive MRI scans
    - Automated quality validation before AI inference
    - Role-separated access for lab technicians vs. doctors
    - Full audit trails for all imaging workflow events
• SecureNeuroGrade addresses all these gaps in one integrated platform.

================================================================================
SLIDE 3 — OBJECTIVES
================================================================================

1. Implement AES-256-GCM encryption for MRI scans at rest (Module M1)
2. Automate scan quality validation: format, file size, resolution (Module M2)
3. Classify brain tumors into 4 classes using EfficientNetB0 Transfer Learning:
   Glioma | Meningioma | Pituitary | No Tumor
4. Assign clinical risk levels: LOW / MODERATE / HIGH / CRITICAL (Module M3)
5. Restrict result access to authorized doctors using RBAC
6. Log all security and workflow events via a tamper-evident audit trail (M4)
7. Deliver a professional web interface for both technicians and doctors

SLIDE 5 — MODULE M1: AES-256-GCM ENCRYPTION
================================================================================

Status:     85% Complete
File:       app/security/encryption.py
            app/services/encryption_service.py

Algorithm:  AES-256-GCM (Authenticated Encryption with Associated Data)
Key:        256-bit (32 bytes) — loaded from ENCRYPTION_KEY env variable
Nonce:      12 bytes — randomly generated per file (os.urandom)
Auth Tag:   16 bytes — detects any tampered byte in the stored file
Format:     Stored as: [nonce 12B] || [auth_tag 16B] || [ciphertext]

Why AES-256-GCM?
  Confidentiality:  2^256 key space — quantum-resilient
  Integrity:        Auth tag catches any bit-level file tampering
  Performance:      Hardware-accelerated via CPU AES-NI instructions
  Standard:         NIST-approved, healthcare and government grade (HIPAA-aligned)

Remaining 15%: Wire encrypt_scan() call into the upload HTTP POST handler
               in app/routes/technician.py before file is written to disk.

SLIDE 7 — AI MODEL: EfficientNetB0 TRANSFER LEARNING
================================================================================

Architecture:   EfficientNetB0 (pre-trained on ImageNet)
Framework:      TensorFlow / Keras
Task:           4-Class Brain Tumor MRI Classification

Dataset:        Kaggle Brain Tumor MRI Dataset (Masoud Nickparvar)
                ~7,023 brain MRI scans — axial, coronal, sagittal views

Classes:
  0: glioma | 1: meningioma | 2: pituitary | 3: no_tumor

Input:          (1, 224, 224, 3) — float32, pixel range [0.0, 1.0]
Output:         (1, 4) — Softmax probability distribution

Split:          Train ~5,000 | Val ~900 | Test ~1,300 (seed=42, reproducible)

Training Strategy:
  Phase 1 (10 epochs): Classifier head only. Base model frozen. LR = 1e-4
  Phase 2 (15 epochs): Fine-tune top 40 EfficientNet layers. LR = 1e-5

Augmentation:   RandomRotation, RandomZoom, RandomFlip, RandomContrast

Training Notebook: train_brain_tumor.ipynb (Kaggle/Colab GPU ready)
Expected Accuracy: >96% (EfficientNetB0 benchmark on this dataset)

================================================================================

Layer               Implementation
──────────────────────────────────────────────────────────────────────────
Authentication      bcrypt password hashing (salted rounds), Flask-Login sessions
Authorization       @role_required server-side decorator, roles: LAB_TECHNICIAN, DOCTOR

Session Security    HttpOnly cookies, SameSite policy
Secret Management   All credentials via .env file — never in code or git
Audit Trail         11 event types logged — no secrets, no raw images in logs
HTTPS               Planned: Waitress/Gunicorn + TLS for production deployment

SLIDE 12 — ROLE-BASED ACCESS CONTROL (RBAC)
================================================================================

Role: LAB_TECHNICIAN
  Permitted:  Login, upload MRI scans, view upload/processing status,
              retry rejected scans (/technician/retry/<scan_id>)
  Restricted: Doctor dashboard, AI results, model configuration

Role: DOCTOR
  Permitted:  Login, view scan results, confidence scores, risk levels,
              patient history, result detail page
  Restricted: Scan upload, admin settings, model config

Enforcement: @role_required decorator on every protected Flask route
             Backend always validates role — frontend hiding is cosmetic only
